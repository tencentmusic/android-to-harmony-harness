# 共建边界与优化评测

各团队可以独立优化下列能力；公共格式和交付判定变更要通过协议评审与回归测试。

| 能力 | 输入 | 输出 / 当前接入位置 | 评测方向 |
| --- | --- | --- | --- |
| 项目知识与定位 | 工程规范、源码、知识库 | project_profile / context；Agent 读取再定点检索 | 定位准确率、过期知识、查找耗时 |
| 工具选择与组合 | 任务目标、工具目录、运行条件 | Profile.tools、task.tool_ids、command argv | 成功率、无效调用、成本 |
| 需求与状态恢复 | Android 代码、需求、正常入口观察 | capabilities、states、来源与基准 | 漏项率、人工补充率 |
| 联合评审 | 需求、方案、UI 与状态映射 | review_scopes、review-packet、approve | 审核耗时、返工率 |
| 工程适配 | 当前生产模块、平台能力 | implement、build、签名包 | 首次构建成功率、回归缺陷 |
| 功能与视觉验收 | 当前包、state_id、合同预期 | points、observations、逐点证据 | 相同覆盖下耗时、误报与漏报 |
| 体验评分 | 单点原始采集、评分规则与版本 | evaluations，作为辅助证据 | 与人工结论一致性、稳定性 |
| 编排与追溯 | 依赖、当前输入、收据、人工结论 | 有效性、coverage、verify、metrics | 错误放行率、恢复成本 |

## 评分服务接入

华为或其他团队的能力先在项目适配器内接入，确认真实接口、许可、输入类型和输出含义。
以 provider/version/metric 标识结果，提供原始响应或可复核文件，并映射到同一 state_id 的验收点。
选取相同样本做人工双盲或独立复核，分别统计误报、漏报及与人工一致性，再决定哪些指标适合成为明确合同断言。
辅助评分本身不决定全流程通过；增加强制指标时应新增断言和评审，不能由适配器自行改变合同 expected。

## 耗时优化

先采集真实项目的 build/install/navigate/wait/assert/capture/compare/cleanup 计时，区分一次性准备、重复执行和失败返工。
固定候选版本、状态清单和断言，比较优化前后的中位数、长尾耗时、稳定性和缺陷检出率。当前版本没有足够真机样本宣称加速比例。

优先项目：共享前置导航、同包安装复用、条件等待、下游视觉复用当前设备原件、失败证据定位、精准输入声明与定向回归。
单设备和同账号发布仍串行。多设备租约、跨包复用和自动依赖推断需单独设计，不能用少验状态或替换真实验收换取速度。

## 责任与测试

每个模块设负责人，同时保留端到端负责人。每次改变协议或门禁必须验证：缺状态、缺基准、缺断言、缺证据、旧包、伪造 passed、
高分掩盖漏验、旧审批、材料变化、进程中断和重复 operation_id。正常闭环与漏验闭环都必须运行。
