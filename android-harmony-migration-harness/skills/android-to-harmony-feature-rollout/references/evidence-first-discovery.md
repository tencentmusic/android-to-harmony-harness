# 先查证再审核

收到来源、目标、入口与现成资料后，先在当前任务恢复事实并生成联合评审材料。
查证结果进入当前合同的 capabilities、states、来源引用与 review_scopes；执行字段以包根
`runtime/harness/CONTRACT.md` 为准。

## 查证

1. 核查源与目标路径、分支、HEAD、用户范围和已有档案，复用仍有效的决定与证据。
2. 从给定入口追创建、调用、绑定、配置条件、请求、状态、失败和清理路径。
   结构化知识库按 wiki → CodeGraph → 定点源码查证；通用工程按其知识来源与模块边界查证。
3. 追踪 XML/Compose/View、资源、主题、产品变体和运行时覆盖，分别记录源码结论与运行观察。
4. 核对状态、开关、账号、版本、缓存、切换与重进条件。冲突结论检查相反分支与实际版本。
5. 每项结论附可复核定位与适用条件；未知项保存已查范围、关键词、候选和具体缺口。

可自行查证的问题继续查证。用户只需决定代码和已有资料无法裁决的业务取舍或必要权限。
工具维护授权不等于业务迁移授权；本协议只为具体任务恢复事实。

## 效果与来源

优先检查用户截图、录屏和已有材料，记录来源、时间、设备、包版本、账号别名与状态。
版本未核对时明确标注；历史图片和源码推导原型分别作为参考，不冒充当前正常入口的设备证据。
缺真实图片时继续恢复代码规则；需要辅助审核时可生成明确标注的推导原型。
正式视觉验收按合同绑定 Android 基线、当前候选包、原始截图与日志。

## 联合评审

生成关联需求、技术、UI、状态和验收点的 HTML，正文展示事实与源码定位、效果来源、冲突与缺口、
需要人工决定的事项及获批后的具体行动。生成文件后实际展示给审核人。
材料与完整静态资源包参与摘要；用户纠正事实后更新受影响的结论，复用未变化的结果。

人工决定对应当前材料摘要并保存真实原话和来源。事实确认、工具升级批准、自审通过均不代替业务批准。
取得实际决定后通过 `approve` 留档；其后按当前依赖和有效批准继续实现、构建、逐点验收与开发交接。
用户仅请求查证或评审准备时，将限定范围记入 session，由 `end-check` 判断本轮是否完成。
